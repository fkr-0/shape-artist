#+title: Shape Artist
#+subtitle: Rapid ASCII Diagram Prototyping for Emacs

* Overview

Shape Artist is an Emacs package for creating ASCII diagrams quickly.
It provides vim-style navigation with automatic shape detection,
making it easy to draw boxes, lines, and labels in plain text.

** Highlights

- Draw with =h/j/k/l= keys, like Vim
- Coherent ASCII and Unicode box detection with malformed-border rejection
- Orthogonal connector bend detection and a derived graph model
- Stable buffer-local shape IDs for parsed rectangles, connectors, and labels
- Shape selection and editing (labels, move, resize)
- Straight connector attachment and sticking during moves
- Normalization: trim, pad, and box with title
- Evil integration with custom states
- Strong theme-aware mode indicators in the header line, mode line, cursor, and sidebar
- Explicit SELECT candidate/multi-selection and SHAPE-EDIT target highlighting
- Sidebar UI with live shape, graph, and guide information
- Buffer-local alignment guides, grid overlays, and guide snapping
- *Edit diagrams in place* in source comments, Org and Markdown blocks, or
  indented text, without taking over the buffer
- *Mouse*: select, drag to move, corner handles to resize, drag to draw, a
  ghost preview, and a context menu
- *Learn in minutes*: a mode-aware key hint, a command palette, a generated
  cheat sheet, an Artist menu, and an interactive tutorial
- *Explain and repair* boxes the parser rejects, and *export* to Mermaid, DOT,
  or SVG
- One undo for everything, including guide changes

* Installation

** Requirements

- Emacs 27.1+
- Evil (optional, for Vim-style states)

** From source

From a source checkout, run:

#+begin_example
eldev test
#+end_example

Add to your init file:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/shape-artist")
(require 'shape-artist)
#+end_src

** From GitHub

With Emacs 29 or later:

#+begin_src emacs-lisp
(package-vc-install "https://github.com/fkr-0/shape-artist")
#+end_src

or, with =use-package= and Emacs 30 or later:

#+begin_src emacs-lisp
(use-package shape-artist
  :vc (:url "https://github.com/fkr-0/shape-artist")
  :commands (shape-artist-scratch shape-artist-edit-at-point

#+end_src

** Local development with straight.el / Doom Emacs

For an actively developed checkout, do not copy package files into the Emacs
configuration and do not maintain a second hand-written symlink tree.  Let
=straight.el= expose the checkout through its build directory.  Its generated
links keep the package manager, autoload generation, and =load-path= ownership
in one place while edits continue to happen in the original Git repository.

A generic straight.el recipe is:

#+begin_src emacs-lisp
(straight-use-package
 '(shape-artist
   :type nil
   :local-repo "/absolute/path/to/artist-shapes"
   :files ("shape-artist*.el" "artist-diagram-*.el")
   :build (:not compile)))
#+end_src

=:type nil= means straight.el must not clone, pull, or otherwise manage the
checkout.  Disabling compilation is useful during development because every
restart loads the current source through straight's generated symlinks rather
than a stale byte-compiled file.

In Doom Emacs, declare the same checkout from =packages.el=:

#+begin_src emacs-lisp
(package! shape-artist
  :type local
  :pin nil
  :recipe (:type nil
           :local-repo "/absolute/path/to/artist-shapes"
           :files ("shape-artist*.el" "artist-diagram-*.el")
           :build (:not compile)))
#+end_src

Then run =doom sync=.  =:type local= also tells Doom that this repository is
modified in place and should not be advanced by normal package updates.

* Usage

=M-x shape-artist-scratch= opens a new artist buffer with the
sidebar.  From there:

1. =d= enters DRAW mode
2. =h/j/k/l= draws lines
3. =SPC= sets an anchor, then move to define a rectangle
4. =RET= commits the shape
5. =C-n= enters SELECT mode to pick a shape
6. =RET= in SELECT locks the shape for editing
7. In SELECT, use =t= to mark multiple shapes or =T= to select all.
8. In SHAPE-EDIT, use =H/J/K/L= to move the locked shape or group, =>= / =<= to change width or edge length, =+= / =_= to change height or vertical edge length, =[= / =]= and ={= / =}= for left/top anchored resize, and =x= to cycle border or arrow style.
9. Press =?= for the mode-aware key hint (press it again for the full command
   palette), =o= for the outline tree, or =z= to center the parsed diagram.
   =u= always undoes, and =a= toggles the sidebar.

** Editing a diagram where it lives

Put point on a diagram inside a comment, an Org or Markdown block, or an
indented text block and run =M-x shape-artist-edit-at-point=.  It opens in its
own buffer with the comment prefix removed; =C-c C-c= writes it back (prefix
restored, everything around it untouched, one undo step) and =C-c C-k= cancels.
Select lines first to edit exactly those.  =M-x shape-artist-insert-diagram=
starts a new diagram below the current line in the same comment style.  Bind
them to keys you like:

#+begin_src emacs-lisp
(global-set-key (kbd "C-c d") #'shape-artist-edit-at-point)
(global-set-key (kbd "C-c D") #'shape-artist-insert-diagram)
#+end_src

** Mouse

Press a shape to select it and drag to move it (a ghost outline previews the
result and the buffer changes on release).  Drag a corner handle of the
selected box to resize it, drag across blank canvas to draw a box, shift-press to
build a group, double-press a box to edit its label, and right-press for a
context menu.  In a terminal, enable =xterm-mouse-mode=.  The sidebar is
clickable too.

** Learning and discovering

Run =M-x shape-artist-tutorial= for a guided practice session with a live
checklist, press =?= for key hints, or open the Artist menu.  =M-x
shape-artist-help-cheatsheet= lists every key of every mode.

** Diagnosing and exporting

=E e= explains why a box is not detected, =E r= repairs it (=E R= repairs every
near-miss), and =E x= exports the diagram as Mermaid, Graphviz DOT, or SVG.

** Modal UX and visual state

The four editing modes intentionally look and behave different.  One central
mode contract drives the Evil adapter, cursor form, mode-line badge, header-line
activity/hint, and sidebar state so those surfaces cannot independently drift.
MOVE is labeled =NAVIGATE=, DRAW =CREATE=, SELECT =PICK=, and SHAPE-EDIT
=TRANSFORM=.  Faces inherit the current Emacs theme instead of imposing fixed
RGB backgrounds, and color is never the only state cue.

SELECT uses separate overlays for the current candidate and shapes retained in
a multi-selection.  SHAPE-EDIT keeps the locked object or group visibly marked
until editing exits.  Disabling Shape Artist restores the prior cursor,
header-line, mode-line, and whitespace presentation.

** Object detection and graph analysis

Rectangle recognition validates a coherent border family instead of accepting
arbitrary mixtures of box punctuation.  Supported families include standard,
heavy, and light ASCII boxes, ASCII rounded boxes, and Unicode single, rounded,
and double boxes.  Unicode border families are retained when parsed rectangles
are moved or redrawn.

Connectors remain editable as straight edge segments, but parsing also derives a
graph layer.  An ASCII =+= bend may participate in both horizontal and vertical
segments; those segments are grouped into logical orthogonal routes.  The graph
provides rectangle adjacency, connected components, and shortest-path analysis,
and the sidebar reports graph node/connection/component counts.  Automatic
obstacle-aware rerouting is deliberately a later feature rather than hidden
inside the parser.

** Guides and grid overlays

Guides are buffer-local alignment aids.  They are visible as overlays, listed in
the sidebar, and never modify the underlying ASCII diagram text.

Common guide commands are available from the =?= quick action menu:

| Command | Purpose |
|---------+---------|
| =shape-artist-guide-create-horizontal= | Add a horizontal guide at the current row. |
| =shape-artist-guide-create-vertical= | Add a vertical guide at the current column. |
| =shape-artist-guide-delete-nearest= | Delete the guide nearest to point. |
| =shape-artist-guide-clear-all= | Remove all guides and guide overlays. |
| =shape-artist-guide-toggle-visibility= | Hide/show all guide overlays while retaining guide state. |
| =shape-artist-guide-toggle-nearest-visibility= | Hide/show one guide. |
| =shape-artist-guide-set-label= | Set or clear a guide label. |
| =shape-artist-guide-set-snap-distance= | Override one guide's snap distance. |
| =shape-artist-guide-edit-properties= | Edit position, label, visibility, and snap distance. |
| =shape-artist-guide-adopt-selection-nearest= | Attach selected/locked shapes to the nearest guide. |
| =shape-artist-guide-clear-adoptions= | Clear guide-to-shape adoption links. |
| =shape-artist-guides-save= | Save guide state to =.shape-artist/guides.el=. |
| =shape-artist-guides-load= | Load guide state for the current file. |
| =shape-artist-guides-delete-saved= | Remove saved guide state for the current file. |
| =shape-artist-guides-undo= | Undo a non-text guide-state change. |
| =shape-artist-guides-redo= | Redo a guide-state change. |
| =shape-artist-snap-toggle= | Enable/disable guide snapping. |
| =shape-artist-grid-toggle= | Hide/show the lightweight grid overlay. |
| =shape-artist-grid-snap-toggle= | Enable/disable snap-to-grid. |
| =shape-artist-grid-set-size= | Change grid spacing. |

When guide snapping is enabled, rectangle moves, edge moves, group moves, and
anchored rectangle resizes magnetize to nearby horizontal/vertical guides within
=shape-artist-guide-snap-distance=.  If grid snapping is enabled and no guide
wins on an axis, the same operation snaps to the configured grid.  Connector
sticking still uses the existing shape move logic after the final snapped delta
is chosen.

Guides can also adopt selected shapes.  Moving an adopted guide drags those
shapes along the guide axis while suppressing recursive guide/grid snapping, so
manual guide moves remain exact and predictable.  Guide-only operations maintain
a small undo/redo stack because overlays, labels, snap distances, and adoption
links are metadata rather than text edits.

** Metadata and stable shape IDs

Every parsed rectangle, connector, and label receives a buffer-local metadata ID
such as =sa-1=.  IDs are best-effort and remain stable across unchanged reparses,
which makes sidebar references, future semantic undo, sidecar metadata, and
export round-tripping easier to build on.  IDs do not alter the ASCII diagram
text.  Use =shape-artist-metadata-save=, =shape-artist-metadata-load=, and
=shape-artist-metadata-delete-saved= to persist or clear IDs for file-backed
buffers in =.shape-artist/metadata.el= under the current project root.

For file-backed buffers, =shape-artist-guides-save= stores guide IDs, labels,
visibility, per-guide snap distances, grid settings, and adoption signatures in
=.shape-artist/guides.el= under the current project root.  The sidecar maps
project-relative file names to guide snapshots, so the diagram text stays clean.
Use =shape-artist-guides-load= to restore the current file's guides.

eldev test

** End-to-end tests

The suite includes modal end-to-end tests that drive active keymaps through
MOVE, DRAW, SELECT, and SHAPE-EDIT.  These tests cover Evil-style operation even
when Evil is absent, plus delayed Evil loading when the dependency is available.

** Coverage

#+begin_example
scripts/coverage.sh              # per-file summary, writes coverage/lcov.info
scripts/coverage.sh --min 95     # also fail below 95% total line coverage
#+end_example

Coverage is measured with =undercover= (edebug-based) in a scratch copy of the
sources, so stale =.elc= files cannot hide a file from the report.  Commands
with a computed =interactive= spec are only credited when a test calls them via
=call-interactively=, so the total slightly under-estimates real coverage.

Two known bugs are recorded as ERT /expected failures/ rather than skipped: the
mode cannot be re-enabled in a buffer that is already in =picture-mode=.  ERT
reports an unexpected pass once they are fixed.
